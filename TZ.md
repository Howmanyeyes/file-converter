# Техническое задание на разработку кросс-платформенного приложения для конвертации файлов

## 1. Название проекта

Рабочее название: **Offline File Converter**

## 2. Назначение приложения

Необходимо разработать кросс-платформенное настольное приложение для локальной конвертации и сжатия файлов.

Приложение должно работать без подключения к интернету. Все операции с файлами должны выполняться непосредственно на устройстве пользователя.

Основной сценарий использования:

1. Пользователь запускает приложение.
2. Перетаскивает файл в область Drag and Drop.
3. Приложение автоматически определяет тип файла.
4. Под областью загрузки отображаются доступные действия для этого типа файла.
5. Пользователь выбирает действие и параметры обработки.
6. Приложение обрабатывает файл.
7. Пользователь сохраняет результат в выбранную папку.

---

## 3. Целевые платформы

MVP должен поддерживать следующие платформы и архитектуры:

### Windows

- Windows 10 и Windows 11;
- Windows x86-64 / AMD64.

### macOS

- macOS на процессорах Apple Silicon;
- архитектура ARM64;
- устройства с процессорами Apple M1, M2, M3, M4 и более новыми.

Поддержка macOS на Intel в MVP не требуется.

---

## 4. Установщики

Для каждой поддерживаемой платформы должен предоставляться отдельный установщик.

### Windows

Необходимо подготовить:

- установщик для Windows x86-64 / AMD64.

Предпочтительные форматы:

- `.exe`;
- либо `.msi`.

Установщик должен:

- запускаться обычным двойным нажатием;
- не требовать установки дополнительных библиотек;
- автоматически устанавливать все необходимые компоненты;
- создавать ярлык в меню «Пуск»;
- при необходимости предлагать создание ярлыка на рабочем столе;
- добавлять приложение в список установленных программ;
- поддерживать стандартное удаление через настройки Windows;
- не требовать использования командной строки.

### macOS

Необходимо подготовить установщик для Apple Silicon.

Предпочтительный формат:

- `.dmg`.

Установка должна выполняться стандартным способом:

1. Пользователь открывает `.dmg`.
2. Перетаскивает приложение в папку `Applications`.
3. Запускает приложение.

Приложение не должно требовать установки Homebrew, Python, Ghostscript, ImageMagick или других внешних зависимостей.

Все необходимые библиотеки должны поставляться вместе с приложением.

---

## 5. Требования к работе без интернета

Приложение должно полностью работать офлайн.

Приложение не должно:

- загружать пользовательские файлы на сервер;
- отправлять содержимое файлов через интернет;
- использовать облачные API для конвертации;
- требовать регистрации;
- требовать авторизации;
- требовать активной подписки;
- требовать интернет-соединения для основных функций.

Все преобразования должны выполняться локально.

В интерфейсе приложения необходимо разместить текст:

> Все файлы обрабатываются локально и не передаются в интернет.

---

## 6. Поддерживаемые форматы в MVP

В MVP необходимо поддерживать только два формата:

- PDF;
- PNG.

Приложение должно автоматически определять формат файла не только по расширению, но и по его фактическому содержимому.

Необходимо поддерживать:

- PDF → PNG;
- PNG → PDF;
- PDF → PDF со сжатием.

Поддержка JPG, JPEG, HEIC, WebP, TIFF и других форматов в MVP не требуется.

## 7. Главный экран

Главный экран должен быть визуально простым и не перегруженным.

На главном экране должны находиться:

1. Название приложения.
2. Краткое описание.
3. Область Drag and Drop.
4. Кнопка выбора файла через системный диалог.
5. Информация о выбранном файле.
6. Блок доступных действий.
7. Параметры выбранного действия.
8. Кнопка запуска обработки.
9. Индикатор прогресса.
10. Информация о результате.

---

## 8. Drag and Drop

В центре главного окна должна находиться заметная область Drag and Drop.

Пример текста:

> Перетащите PDF или PNG сюда

Под текстом должна находиться кнопка:

> Выбрать файл

Область должна визуально реагировать на перетаскивание:

- подсвечиваться;
- менять границу;
- показывать состояние готовности принять файл.

После добавления файла приложение должно автоматически:

1. Проверить файл.
2. Определить его формат.
3. Проверить, поддерживается ли формат.
4. Показать имя файла.
5. Показать размер файла.
6. Показать тип файла.
7. Для PDF показать количество страниц.
8. Для PNG показать разрешение изображения.
9. Показать доступные действия.

---

## 9. Автоматическое определение типа файла

После добавления файла приложение должно определить:

- является ли файл PDF;
- является ли файл PNG;
- является ли файл повреждённым;
- соответствует ли содержимое файла его расширению.

Пример:

Если файл имеет расширение `.pdf`, но фактически не является PDF, приложение должно показать понятную ошибку.

Текст ошибки:

> Файл имеет расширение PDF, но его содержимое не соответствует формату PDF.

Если формат не поддерживается:

> Этот формат пока не поддерживается. В текущей версии можно использовать только PDF и PNG.

## 10. Действия для PDF

Если пользователь добавил PDF, под областью Drag and Drop должны автоматически появиться следующие действия:

### 10.1. Конвертировать PDF в PNG

Пользователь должен иметь возможность:

- преобразовать все страницы;
- выбрать диапазон страниц;
- выбрать отдельные страницы;
- указать разрешение;
- выбрать папку сохранения.

Предустановленные значения разрешения:

- 72 DPI;
- 96 DPI;
- 150 DPI;
- 200 DPI;
- 300 DPI.

Значение по умолчанию:

- 150 DPI.

Каждая страница должна сохраняться отдельным PNG-файлом.

Пример именования:

```text
document_page_001.png
document_page_002.png
document_page_003.png
```

Нумерация должна учитывать общее количество страниц и использовать ведущие нули.

### 10.2. Сжать PDF

Пользователь должен иметь возможность уменьшить размер PDF.

В MVP необходимо реализовать три режима:

#### Минимальное сжатие

- максимальное сохранение качества;
- небольшое уменьшение размера;
- подходит для печати и хранения.

#### Сбалансированное сжатие

- заметное уменьшение размера;
- сохранение читаемости текста;
- режим по умолчанию.

#### Сильное сжатие

- максимальное уменьшение размера;
- допускается заметное снижение качества изображений.

После сжатия необходимо показать:

- исходный размер;
- итоговый размер;
- уменьшение в мегабайтах;
- уменьшение в процентах.

Пример:

```text
Исходный размер: 30,2 МБ
Итоговый размер: 4,8 МБ
Уменьшение: 25,4 МБ — 84%
```

Приложение не должно обещать получение конкретного размера для любого документа.

### 10.3. Обрезать белые поля

В MVP необходимо предусмотреть функцию автоматического обнаружения и обрезки пустых полей на страницах PDF.

Параметры:

- включить или отключить обрезку;
- чувствительность определения белого фона;
- минимальный сохраняемый отступ.

Функция должна учитывать:

- полностью белый фон;
- светло-серый фон;
- небольшие следы сканирования по краям.

Обрезка белых полей может использоваться совместно со сжатием PDF.

## 11. Действия для PNG

Если пользователь добавил PNG, под областью Drag and Drop должны автоматически появиться следующие действия:

### 11.1. Конвертировать PNG в PDF

Пользователь должен иметь возможность создать PDF из одного PNG-файла.

Параметры:

- размер страницы по изображению;
- размер страницы A4;
- книжная ориентация;
- альбомная ориентация;
- автоматическая ориентация;
- поля;
- режим размещения изображения.

Режимы размещения:

- вписать изображение целиком;
- заполнить страницу с обрезкой;
- использовать исходный размер.

Значения по умолчанию:

- размер страницы по изображению;
- автоматическая ориентация;
- изображение вписывается целиком.

### 11.2. Сжать PNG

В MVP желательно предусмотреть уменьшение размера PNG без изменения формата.

Возможные методы:

- оптимизация структуры PNG;
- удаление необязательных метаданных;
- уменьшение разрешения;
- преобразование в индексированную палитру, если это не приводит к заметной потере качества.

Пользователь должен иметь возможность:

- оставить исходное разрешение;
- уменьшить изображение в процентах;
- задать максимальную ширину;
- задать максимальную высоту;
- сохранить пропорции.

## 13. Логика отображения действий

До загрузки файла блок действий не отображается или находится в неактивном состоянии.

После загрузки PDF отображаются только действия, доступные для PDF:

- PDF → PNG;
- сжатие PDF;
- обрезка белых полей.

После загрузки PNG отображаются только действия, доступные для PNG:

- PNG → PDF;
- сжатие PNG.

Недоступные действия не должны показываться.

## 14. Информация о файле

После загрузки файла необходимо показать карточку со следующими данными:

- имя файла;
- расширение;
- фактический формат;
- размер;
- путь к файлу;
- дата изменения;
- статус проверки.

Для PDF дополнительно:

- количество страниц;
- размер страниц, если возможно определить;
- наличие пароля;
- наличие текстового слоя, если это можно определить без значительного усложнения.

Для PNG дополнительно:

- ширина;
- высота;
- цветовая модель;
- наличие прозрачности.

## 15. Сохранение результата

Пользователь должен иметь возможность:

- сохранить результат рядом с исходным файлом;
- выбрать другую папку;
- открыть системный диалог сохранения.

По умолчанию исходный файл не должен перезаписываться.

Примеры имён:

```text
document_compressed.pdf
document_page_001.png
image_converted.pdf
image_optimized.png
```

При совпадении имён приложение должно автоматически добавлять номер:

```text
document_compressed_2.pdf
```

Обработка страницы 7 из 24

После завершения операции необходимо показать:

- статус;
- путь к готовому файлу или папке;
- исходный размер;
- итоговый размер;
- длительность операции;
- количество обработанных страниц;
- возможные предупреждения.

Кнопки:

- «Открыть файл»;
- «Открыть папку»;
- «Показать в Finder» на macOS;
- «Показать в Проводнике» на Windows;

## 18. Обработка ошибок

Приложение должно корректно обрабатывать:

- повреждённые PDF;
- повреждённые PNG;
- PDF, защищённые паролем;
- файлы без прав на чтение;
- папки без прав на запись;
- нехватку свободного места;
- отмену операции;
- закрытие приложения во время обработки;
- неподдерживаемые форматы;
- файлы с неправильным расширением.

Сообщения должны быть понятными.

Плохо:

```text
Error 0x00000214
```

Хорошо:

```text
Не удалось открыть PDF. Файл повреждён или защищён паролем.
```

Технические детали можно показывать в раскрываемом блоке.

---

## 19. Производительность

Приложение должно:

- не блокировать интерфейс;
- выполнять обработку в фоне;
- использовать несколько ядер процессора, если это безопасно;
- корректно работать с большими PDF;
- обрабатывать документы размером не менее 500 МБ;
- использовать постраничную обработку;
- не загружать весь большой PDF в оперативную память без необходимости;
- удалять временные файлы после завершения;
- не повреждать исходные файлы.

---

## 20. Безопасность и приватность

Приложение должно:

- работать полностью локально;
- не отправлять содержимое файлов;
- не отправлять названия файлов;
- не отправлять пути к файлам;
- не хранить историю без согласия пользователя;
- не собирать аналитику в MVP;
- не содержать рекламных SDK;
- не содержать облачных функций.

## 21. Техническая реализация

Приложение должно использовать единую кросс-платформенную кодовую базу, насколько это возможно.

Допустимые варианты:

- Tauri;
- Flutter;
- Qt;
- .NET с кросс-платформенным UI;
- Electron, если размер приложения и потребление памяти будут приемлемыми.

Предпочтительный вариант:

- Python для логики приложения и локальной обработки файлов;
- PySide6 / Qt 6 для кросс-платформенного интерфейса;
- QSS для оформления интерфейса.

Причины:

- поддержка Windows x86-64;
- поддержка macOS ARM64;
- единая основная кодовая база на Python;
- возможность создания современного нативного интерфейса;
- выполнение тяжёлых операций в нативных PDF- и PNG-библиотеках;
- возможность фоновой и параллельной обработки через отдельные процессы;
- отсутствие зависимости от системного браузерного движка.

Допускается другой стек, если он обеспечивает все требования MVP.

## 26. Критерии приёмки

### Проверка 1. Установка

1. Запустить установщик на Windows x86-64.
2. Установить приложение.
3. Установить приложение через `.dmg` на Mac с Apple Silicon.

Ожидаемый результат:

- установка проходит без командной строки;
- не требуется установка дополнительных компонентов;
- приложение запускается после установки.

### Проверка 2. Работа без интернета

1. Отключить интернет.
2. Запустить приложение.
3. Добавить PDF.
4. Конвертировать его в PNG.
5. Сжать PDF.
6. Добавить PNG.
7. Конвертировать PNG в PDF.

Ожидаемый результат:

- все операции выполняются без интернета;
- приложение не требует авторизации;
- файлы не передаются во внешние сервисы.

### Проверка 3. Автоматическое определение PDF

1. Перетащить PDF в приложение.

Ожидаемый результат:

- определяется тип PDF;
- показывается имя файла;
- показывается размер;
- показывается количество страниц;
- появляются действия PDF → PNG и «Сжать PDF».

### Проверка 4. Автоматическое определение PNG

1. Перетащить PNG в приложение.

Ожидаемый результат:

- определяется тип PNG;
- показывается разрешение;
- показывается наличие прозрачности;
- появляется действие PNG → PDF.

### Проверка 5. PDF → PNG

1. Добавить PDF из 10 страниц.
2. Выбрать 150 DPI.
3. Запустить обработку.

Ожидаемый результат:

- создаются 10 PNG-файлов;
- страницы сохраняются в правильном порядке;
- файлы имеют последовательные имена;
- все файлы открываются стандартными средствами системы.

### Проверка 6. PNG → PDF

1. Добавить PNG.
2. Выбрать размер страницы по изображению.
3. Запустить обработку.

Ожидаемый результат:

- создаётся PDF;
- изображение не искажается;
- прозрачность корректно обрабатывается;
- PDF открывается стандартными средствами системы.

### Проверка 7. Сжатие PDF

1. Добавить PDF размером около 30 МБ.
2. Выбрать сбалансированное сжатие.
3. Включить обрезку белых полей.
4. Запустить обработку.

Ожидаемый результат:

- создаётся новый PDF;
- размер файла уменьшается, если содержимое допускает сжатие;
- страницы не теряются;
- текст остаётся читаемым;
- показывается исходный и итоговый размер.

### Проверка 8. Неподдерживаемый формат

1. Перетащить JPG или другой неподдерживаемый файл.

Ожидаемый результат:

- приложение не пытается обработать файл;
- отображается сообщение о поддержке только PDF и PNG.

### Проверка 9. Повреждённый файл

1. Перетащить повреждённый PDF.

Ожидаемый результат:

- приложение не закрывается аварийно;
- отображается понятное сообщение об ошибке;
- интерфейс остаётся доступным.
